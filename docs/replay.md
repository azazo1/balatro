# 回放

录制时每局写一份回放文件 `<录像同名>.replay.json` (`replay/log.lua`), 记下开局参数, 开局时的存档进度,
每一步操作, 以及内置 agent 的模型输出 (第一个字和结束的时间, 加上思维链和正文). 回放用同一个种子开局,
恢复原局的存档进度, 再按顺序重做每一步, 画面与声音由游戏自己产生; 顶部流式条按这段时间的平均字速滚输出.
下文的路径都在 `mods/bbreplay/` 下; 每一步由 bbcore 的端点执行, 所以不装 balatrobot 也能回放.

两种入口共用同一套播放器 (`replay/player.lua`):

- 命令行: `just macos replay <回放文件>`, 见 [agent-api.md](<agent-api.md>) 的 "回放" 一节. 用环境变量指定
  回放文件, 用临时存档 `Balatro-Replay` 隔离, 放完后以退出码结束进程.
- 游戏内: 主菜单 选项 -> 回放. 不需要命令行, Android 上同样能用. 下文主要讲这一种.

## 入口与列表

入口: ESC 菜单 (Android 上是 "选项") 新增 "回放" 按钮.

- 只在主菜单显示, 因为回放要从开局开始.
- 所有平台都有, 与 agent 模式无关.

回放列表:

- 扫描录像目录下的回放文件, 按时间倒序分页显示. 两种布局都认: 每局一个文件夹 `<stem>/<stem>.replay.json`,
  与旧版平铺的 `<stem>.replay.json`.
- 每行显示: 开始时间 (按本机时区显示), 牌组, 赌注, 种子, 结果 (胜负, 底注), 步数, 原局时长.
- 不能回放的文件 (版本不支持, 挑战模式, 非原版牌组, 文件损坏, 没有可重做的操作) 变灰, 并注明原因.
  这些行仍可点进确认页, 页面上只显示原因与 "删除".
  早先的版本只记了手动操作的次数, 那时手动打的局没有具体操作, 属于最后一种.
- 判断能否回放需要解析整个文件, 而文件里带存档快照, 可能较大. 解析结果按 文件名, 大小, 修改时间 缓存.
- 点一行进入确认页:
  - 显示回放前的提示 (版本不一致, 旧文件里只记了次数的手动操作).
  - 选择节奏 (原速 original / 紧凑 tight / 快进 fast), 是否录像. 紧凑下右侧消息更快退去; 快进的间隔同紧凑,
    讲解的阅读时长几乎为零, 弹出后随即做下一步; 框本身仍停留约 1.5 秒 (滑入就要 0.3~0.4 秒, 停留再短
    就看不到), 且不排队, 新的直接叠在上面. 工具调用那条左侧始终用短时长; 回放自己的提示 (警告,
    中止方法, 结果) 不跟节奏走.
    顶部流式条按录制时的起止时间以平均字速滚模型输出; 紧凑与快进把原局那段思考压进两步之间的短等待.
  - 然后开始回放. 回到列表用面板底部原版的 "返回".
  - "删除": 点一次变成 "再点一次删除", 3 秒内再点才删, 删完回到列表. 每局一个文件夹的局删掉整个文件夹
    (里面的视频, 时间轴, 回放文件, agent 转录与残留的中间文件); 旧版平铺的局不给删, 按钮是灰的, 因为
    那些文件散在录像目录根下, 与别的局混在一起, 删错就是误删. 中间文件 10 秒内还在变化时 (局末合成在
    后台进行) 不删. 删除不能撤销.

## 手动操作的录制

人手动打的局也能回放 (`replay/manual.lua`).

- 人点的按钮和 agent 的接口走同一批游戏函数, 给它们套一层, 按调用时的选中状态换算成一步,
  标 `manual = true`.
- 只算在 `UIElement:click` 里面发生的调用: 鼠标, 触摸, 手柄的按钮都经过它; 接口传的是假按钮,
  游戏自己在事件里的调用 (The Hook 自动弃牌, 标签送的卡包, 读档时重开卡包, 买了直接用里的那次
  `use_card`) 都不经过它, 回放时它们同样会发生. 只看 "agent 没在处理请求" 不够: 弹窗出现时请求
  会先返回, 它后续的事件还会调用这些函数.
- 接口与人点等价的照接口回放; 接口比人的操作限制多的记成本地步骤 `press`, 回放时用同样的方式
  调用同一个按钮函数:

  | 游戏函数 | 回放步骤 |
  |---|---|
  | `play_cards_from_highlighted`, `discard_cards_from_highlighted` | `play`, `discard` (选中的牌) |
  | `select_blind`, `skip_blind`, `reroll_boss` | `select`, `skip`, `reroll_boss` |
  | `reroll_shop`, `cash_out`, `toggle_shop` | `reroll`, `cash_out`, `next_round` |
  | `use_card` 用在商店的优惠券, 卡包上 | `buy {voucher}`, `buy {pack}` |
  | `use_card` 用在卡包里的牌, 消耗牌上 | `press`, 带手里选中的牌 |
  | `buy_from_shop` (含 "买了直接用"), `sell_card`, `skip_booster` | `press` |
  | `sort_hand_suit`, `sort_hand_value` | `press` (没有接口) |
  | 拖动排序 (手牌, 小丑, 消耗牌) | 本地步骤 `reorder` |

  接口的限制: `use`, `sell` 只允许在出牌, 商店和开卡包时用, 人在选盲注, 结算时也能用和卖;
  `pack` 选完等的是回到商店, 标签送的
  卡包关上后回到选盲注; `use` 对 Aura 忽略传入的目标. 排序按钮改的是之后发牌也沿用的排序方式,
  只记一次重排的结果不够.
- 拖动排序不经过按钮函数: 每帧在没有拖动时记下顺序, 拖动结束时比较. 牌数变了 (拖去卖掉) 不算排序.
  `reorder` 不用 `rearrange` 接口, 因为人在选盲注时也能拖小丑, 而接口不允许.
- 回放 `press` 时指向的牌还不在 (例如标签送的卡包还没打开) 就下一帧再试; 做完后等它触发的动画
  停下才算完成. 回放文件是外部输入, `press` 只调用名单里的函数, 只指向名单里的区域.
- 手动步骤没有 "完成" 的时刻, 状态摘要在下一步开始时取, 那时人看着的画面已经停下; 回放时同样等
  动画停下再比. 拖动可能发生在上一步的动画中途, 回主菜单时这一局已经在拆, 所以这两种步骤之前的那一步
  不比对.
- 教程局: 强制给出的优惠券, 标签和商店里的牌都是写死的常量, 不走随机, 所以能回放. 回放文件里的
  `run.tutorial` 标记这种局 (旧文件按 "种子是 TUTORIAL 且没有手动指定" 判断); 开局前按快照里的教程状态
  放回去, 见 [tutorial.lua](<../mods/bbreplay/replay/tutorial.lua>).
- 教程引导 (要点 "下一句" 的那些浮层) 在回放里不显示, 但每一步的推进照常: 教程在那几步里清掉强制标签
  与强制优惠券, 时机关系到后面抽到什么, 不能整段跳过.

## 存档隔离

- 运行中切换存档标识会和后台的存档线程冲突, 所以不切换存档, 改为拦截写入.
- 开始前等存档线程把排队的写入做完.
- 回放期间丢弃所有存档写入. 写入有两个出口: `G.SAVE_MANAGER.channel` 上的请求, 以及主线程直接调用的 `compress_and_save` (`game.lua` 和 `functions/misc_functions.lua`). 这样磁盘上的真实存档, 进度和设置都不会被改动, 回放中途崩溃也一样.
- 然后在内存里套用原局的快照.
- 结束后用 `load_profile` 从磁盘重新读回当前档位的进度, 设置恢复成开始前的副本.
- 主菜单 "继续" 读取的仍是真实的 `save.jkr`, 不受回放影响.
- 读档开局的回放需要先把存档写成临时文件交给 `load`. 这次写入要放行, 并且用完即删.

## 互斥, 中止与结束

互斥:

- 回放进行时, 内置 loop 不能开始; 外部模式暂停监听, 回放结束后恢复.
- 内置 loop 正在运行或暂停时, 回放按钮不可用.
- 两个 mod 不直接互相调用, 都通过 bbcore 的 `BB_CONTROL`: player 开始时申请独占 (`claim`), 结束时释放;
  balatrobot 把内置 loop 登记为忙 (`add_busy`), 并在独占变化时重新按模式启停监听 (`on_change`).
  命令行回放在 bbreplay 加载时就登记独占, balatrobot 的首次启停推迟到所有 mod 加载完, 所以端口不会先开再关.

画面窗口最右上角 (与内置 agent 同一套 HUD, 贴窗口边而不是内容区边上):

按钮文字显示当前状态 (与节奏按钮一致), 不是点下去要做的事:

- 播放中/已暂停: 点一下切换. 暂停时不再做下一步, 已经发出去的请求仍等结果. 暂停期间原局间隔与超时一起往后挪, 不会被暂停吃掉.
  屏幕上的讲解也停住计时, 排队的不放出来, 继续后接着走; 回放自己的提示和正在退场的照常走完.
- 节奏: 显示当前节奏, 点一下按 原速 -> 紧凑 -> 快进 循环切换, 与确认页的选项相同. 切换后屏幕上的讲解
  按新档位重算停留 (已经够时长的随即退场), 下一步的间隔按新节奏算. 游戏动画不受影响.
- 中止: 立刻停, 与按住 Esc 到头相同. 若开局请求已经发出但还没进局, 等开局完成 (或超时)
  再收尾, 避免一边进局一边拆存档 / 回主菜单 (会叠一层转场, 原版 wipe_off 空引用崩溃).
  还在主菜单 (开局前中止) 就不必再走一遍回主菜单.

中止的其它办法:

- 桌面: 按住 Esc 1 秒. 手柄: 按住 back (或 start) 1 秒. 窗口失去焦点时清零, 免得收不到松开而自己中止.
- 触摸: 长按屏幕 1.5 秒, 按在右上角 HUD 上的手指不算 (否则点一下暂停也会闪中止进度).
  按住时长每帧按 `love.touch.getTouches()` 判断. 不能靠 `love.touchpressed`: 游戏的主循环
  (`game/main.lua` 的 `love.run`) 收到 `touchpressed` 只记一个标记, 改由 `mousepressed` 带上 "是触摸"
  传下去, 从不调用 `love.touchpressed`. 早先按事件判断, 真机上长按没有反应.
- 按住期间顶部显示 "按住中止回放 (x%), 松开取消". 回放开始时用一条消息说明中止方法.

输入锁 (`replay/input_lock.lua`) 是 bbcore 输入门 (`BB_INPUT`, 见 [modding.md](<modding.md>) 的内置 mod 一节)
上的一个策略, 从上锁一直生效到收尾的停留结束:

- 丢掉对游戏的全部操作; 点在右上角 HUD 上的由输入门交给 HUD, 松开在同一颗按钮上才算点击.
- 游戏读到的光标停在左上角, 真实光标经过牌时不会触发悬停并录进视频; 光标在 HUD 上时仍用真实坐标.
- 移动照常放行: 原版只用它切换系统指针的显隐 (用鼠标时显示, 触摸时藏起). 系统指针显示在真实位置,
  录像读回的是游戏画布, 不含它. 命令行回放开局时还没动过鼠标, 原版的指针是藏着的, 所以上锁时按最近的
  输入方式设一次.
- 手柄的摇杆与扳机不轮询.
- 按下与松开成对处理, 回放开始前按住的键在回放中松开, 游戏照样收到.

录像: 和命令行回放一样, 输出 `replay-*` 的视频 (同样是一个文件夹), 按确认页的选择决定是否录制.

结束 (完成, 跑偏或中止都一样):

1. 结束录像段.
2. 用消息显示结果: 完成 / 在第 N 步跑偏 (注明不一致的项) / 已中止.
3. 回到主菜单, 按上面的方法恢复进度和设置, 恢复 agent 模式.

命令行回放仍然以退出码结束进程.

## 实现

| 文件 | 职责 |
|---|---|
| `main.lua` | 入口: 装载录像与回放, 挂钩子的顺序, 跟随 agent 的暂停与停止 |
| `migrate.lua` | 配置迁移 (把旧版 balatrobot 配置里的录像设置搬过来) |
| `replay/log.lua` | 录制时写回放文件, 手动步骤的状态摘要, 模型输出的起止时间 |
| `replay/stream_play.lua` | 回放流式条: 平均字速, 时间映射, 录制累积 (纯逻辑) |
| `replay/manual.lua` | 手动操作换算成回放步骤, 回放时重做本地步骤 |
| `replay/library.lua` | 扫描 `*.replay.json`, 解析列表字段, 判断能不能回放, 缓存与分页 |
| `replay/session.lua` | 等存档线程写完, 装上写入拦截, 结束后读回进度与设置 |
| `replay/tutorial.lua` | 教程局: 放回教程状态, 引导不显示浮层, 收尾恢复 |
| `replay/player.lua` | 两种入口共用的回放驱动, 游戏内以回调结束而不是退出进程 |
| `replay/input_lock.lua` | 输入锁 (输入门上的策略), 中止的按住时长与进度 |
| `ui/replay_menu.lua` | 选项菜单里的回放入口, 列表页与确认页 |
| `ui/settings_tab.lua` | 本 mod 的设置页: 录像开关, 保留方式, 状态 |

- 列表用 `SMODS.NFS` 按目录取一次信息 (`getDirectoryItemsInfo`), 只解析文件名, 大小与修改时间有变化的
  文件; 解析出的 `snapshot` 与 `actions` 不留着, 真正开始时由 player 重新读一遍文件.
- 写入拦截换的是 `G.SAVE_MANAGER.channel` 与全局的 `compress_and_save`, 不碰录像输出 (录像不走存档写入).
  读档开局的临时存档文件在这里放行并登记, 结束时删掉.
- 恢复分两步: 先 `load_profile` 从磁盘读回当前档位 (磁盘没被改动, 读到的就是回放前的状态), 再按开始前
  取的内存快照把解锁, 发现, 累计数据, 设置与教程状态放回去. 这两步都在拦截还装着的时候做, 期间游戏标脏的
  保存请求会被丢掉, 之后才按恢复后的状态落盘.
- 互斥: 回放期间 `BB_CONTROL.owner()` 为 "回放", balatrobot 的 mode `apply()` 因此停掉外部监听并锁定切换;
  内置 loop 的 `can_start` 也据此拒绝启动. 开始前若内置 loop 在运行, 确认页的开始按钮不可点.
- 录制器的开关与文件名前缀运行时可设 (`record/recorder.lua` 的 `set_enabled` / `set_prefix`):
  游戏内回放选了录像时按 `replay-` 前缀录, 结束或开始失败时回滚. 选不录时只把开关关掉, 开局钩子若已装上
  也不会开新的录像段. 录像本来关着时, 选录这一步才装载编码相关的模块并挂上钩子; 回放文件由 `log.lua`
  补写, 因为录制器的开局钩子在这种情况下装得比它晚, 开局那一刻录像段还没建立.
- 回放文件不走 `love.filesystem` 的写包装, 写完后单独通知 Android 修正权限 (见 [android.md](<android.md>)).
- `streams` 是可选字段, 不抬文件版本号. 旧文件没有它时流式条不出现. 每一段是
  `{ wall, wall_end, label?, segments: [{ kind, text }] }`, `wall` 是第一个字到达,
  `wall_end` 是请求结束; 回放按这段时间的总字数匀速露出. original 与原局思考时间对齐,
  tight 与 fast 把这段压进两步之间的短等待.
- 节奏对应 bbcore toast 的右侧时长档位 (`toast.set_pace`): original -> normal, tight -> compact,
  fast -> fast. fast 档连 notify 显式给的 `duration` 也不等; push 时带 `fixed` 的消息不跟档位走. 只有内置 agent 会写入; 外部 agent 没有流式条.
  回放结束用 `toast.apply_home` 恢复 agent 设置页里的消息节奏 (阅读 / 快速; 快速时关掉门槛).
