# 回放

录制时每局写一份回放文件 `<录像同名>.replay.json` (`replay/log.lua`), 记下开局参数, 开局时的存档进度
和每一步操作. 回放用同一个种子开局, 恢复原局的存档进度, 再按顺序重做每一步, 画面与声音由游戏自己产生.
下文的路径都在 `mods/bbreplay/` 下; 每一步由 bbcore 的端点执行, 所以不装 balatrobot 也能回放.

两种入口共用同一套播放器 (`replay/player.lua`):

- 命令行: `just macos replay <回放文件>`, 见 [agent-api.md](<agent-api.md>) 的 "回放" 一节. 用环境变量指定
  回放文件, 用临时存档 `Balatro-Replay` 隔离, 放完后以退出码结束进程.
- 游戏内: 主菜单 选项 -> 回放. 不需要命令行, Android 上同样能用. 下文主要讲这一种.

## 入口与列表

入口: ESC 菜单 (Android 上是 "选项") 新增 "回放" 按钮.

- 只在主菜单显示, 因为回放要从开局开始.
- 所有平台都有, 与 agent 模式无关.

回放列表:

- 扫描录像目录下的 `*.replay.json`, 按时间倒序分页显示.
- 每行显示: 开始时间, 牌组, 赌注, 种子, 结果 (胜负, 底注), 步数, 原局时长.
- 不能回放的文件 (版本不支持, 挑战模式, 教程局, 非原版牌组, 文件损坏, 没有可重做的操作) 变灰, 并注明原因.
  这些行仍可点进确认页, 页面上只显示原因与 "删除".
  早先的版本只记了手动操作的次数, 那时手动打的局没有具体操作, 属于最后一种.
- 判断能否回放需要解析整个文件, 而文件里带存档快照, 可能较大. 解析结果按 文件名, 大小, 修改时间 缓存.
- 点一行进入确认页:
  - 显示回放前的提示 (版本不一致, 旧文件里只记了次数的手动操作).
  - 选择节奏 (tight / original), 是否录像.
  - 然后开始回放. 回到列表用面板底部原版的 "返回".
  - "删除": 点一次变成 "再点一次删除", 3 秒内再点才删, 删完回到列表. 删掉这一局的全部文件: 回放文件,
    完整版与剪辑版视频, 时间轴, agent 转录, 以及崩溃或合成失败留下的中间文件. 只按固定后缀拼出文件名,
    同一局的其它段 (`<stem>-2`) 和回放录下的 `replay-*` 不受影响 (它们各有自己的回放文件或不在列表里).
    中间文件 10 秒内还在变化时 (局末合成在后台进行) 不删. 删除不能撤销.

## 手动操作的录制

人手动打的局也能回放 (`replay/manual.lua`).

- 人点的按钮和 agent 的接口走同一批游戏函数, 给它们套一层, 按调用时的选中状态换算成一步,
  标 `manual = true`.
- 只算在 `UIElement:click` 里面发生的调用: 鼠标, 触摸, 手柄的按钮都经过它; 接口传的是假按钮,
  游戏自己在事件里的调用 (The Hook 自动弃牌, 标签送的卡包, 读档时重开卡包, 买了直接用里的那次
  `use_card`) 都不经过它, 回放时它们同样会发生. 只看 "agent 没在处理请求" 不够: 弹窗出现时请求
  会先返回, 它后续的事件还会调用这些函数.
- 接口与人点等价的照接口回放; 接口比人的操作限制多的记成本地步骤 `press`, 回放时用同样的方式
  调用同一个按钮函数:

  | 游戏函数 | 回放步骤 |
  |---|---|
  | `play_cards_from_highlighted`, `discard_cards_from_highlighted` | `play`, `discard` (选中的牌) |
  | `select_blind`, `skip_blind` | `select`, `skip` |
  | `reroll_shop`, `cash_out`, `toggle_shop` | `reroll`, `cash_out`, `next_round` |
  | `use_card` 用在商店的优惠券, 卡包上 | `buy {voucher}`, `buy {pack}` |
  | `use_card` 用在卡包里的牌, 消耗牌上 | `press`, 带手里选中的牌 |
  | `buy_from_shop` (含 "买了直接用"), `sell_card`, `skip_booster` | `press` |
  | `reroll_boss`, `sort_hand_suit`, `sort_hand_value` | `press` (没有接口) |
  | 拖动排序 (手牌, 小丑, 消耗牌) | 本地步骤 `reorder` |

  接口的限制: `use`, `sell` 只允许在出牌和商店时用, 人在选盲注, 结算, 开卡包时也能用和卖;
  `buy` 的槽位检查不算负片多出的一格, 也没有 "买了直接用"; `pack` 选完等的是回到商店, 标签送的
  卡包关上后回到选盲注; `use` 对 Aura 忽略传入的目标. 排序按钮改的是之后发牌也沿用的排序方式,
  只记一次重排的结果不够.
- 拖动排序不经过按钮函数: 每帧在没有拖动时记下顺序, 拖动结束时比较. 牌数变了 (拖去卖掉) 不算排序.
  `reorder` 不用 `rearrange` 接口, 因为人在选盲注时也能拖小丑, 而接口不允许.
- 回放 `press` 时指向的牌还不在 (例如标签送的卡包还没打开) 就下一帧再试; 做完后等它触发的动画
  停下才算完成. 回放文件是外部输入, `press` 只调用名单里的函数, 只指向名单里的区域.
- 手动步骤没有 "完成" 的时刻, 状态摘要在下一步开始时取, 那时人看着的画面已经停下; 回放时同样等
  动画停下再比. 拖动可能发生在上一步的动画中途, 回主菜单时这一局已经在拆, 所以这两种步骤之前的那一步
  不比对.
- 教程局不可回放: 教程会强制给出优惠券, 标签和商店里的牌, 用 `start` 开局重现不了.
  开局前从 `G.SETTINGS` 判断并写进 `run.tutorial`; 旧文件按 "种子是 TUTORIAL 且没有手动指定" 判断.

## 存档隔离

- 运行中切换存档标识会和后台的存档线程冲突, 所以不切换存档, 改为拦截写入.
- 开始前等存档线程把排队的写入做完.
- 回放期间丢弃所有存档写入. 写入有两个出口: `G.SAVE_MANAGER.channel` 上的请求, 以及主线程直接调用的 `compress_and_save` (`game.lua` 和 `functions/misc_functions.lua`). 这样磁盘上的真实存档, 进度和设置都不会被改动, 回放中途崩溃也一样.
- 然后在内存里套用原局的快照.
- 结束后用 `load_profile` 从磁盘重新读回当前档位的进度, 设置恢复成开始前的副本.
- 主菜单 "继续" 读取的仍是真实的 `save.jkr`, 不受回放影响.
- 读档开局的回放需要先把存档写成临时文件交给 `load`. 这次写入要放行, 并且用完即删.

## 互斥, 中止与结束

互斥:

- 回放进行时, 内置 loop 不能开始; 外部模式暂停监听, 回放结束后恢复.
- 内置 loop 正在运行或暂停时, 回放按钮不可用.
- 两个 mod 不直接互相调用, 都通过 bbcore 的 `BB_CONTROL`: player 开始时申请独占 (`claim`), 结束时释放;
  balatrobot 把内置 loop 登记为忙 (`add_busy`), 并在独占变化时重新按模式启停监听 (`on_change`).
  命令行回放在 bbreplay 加载时就登记独占, balatrobot 的首次启停推迟到所有 mod 加载完, 所以端口不会先开再关.

中止:

- 桌面: 按住 Esc 1 秒. 这是现有做法.
- 触摸: 长按屏幕 1.5 秒. 输入锁仍然丢弃触摸事件, 按住时长每帧按 `love.touch.getTouches()` 判断.
  不能靠 `love.touchpressed`: 游戏的主循环 (`game/main.lua` 的 `love.run`) 收到 `touchpressed` 只记一个标记,
  改由 `mousepressed` 带上 "是触摸" 传下去, 从不调用 `love.touchpressed`. 早先按事件判断, 真机上长按没有反应.
- 按住期间显示进度, 松手就消失. 回放开始时用一条消息说明中止方法.

录像: 和命令行回放一样, 输出 `replay-*` 的完整版和剪辑版, 按确认页的选择决定是否录制.

结束 (完成, 跑偏或中止都一样):

1. 结束录像段.
2. 用消息显示结果: 完成 / 在第 N 步跑偏 (注明不一致的项) / 已中止.
3. 回到主菜单, 按上面的方法恢复进度和设置, 恢复 agent 模式.

命令行回放仍然以退出码结束进程.

## 实现

| 文件 | 职责 |
|---|---|
| `main.lua` | 入口: 装载录像与回放, 挂钩子的顺序, 跟随 agent 的暂停与停止 |
| `migrate.lua` | 配置迁移 (把旧版 balatrobot 配置里的录像设置搬过来) |
| `replay/log.lua` | 录制时写回放文件, 手动步骤的状态摘要 |
| `replay/manual.lua` | 手动操作换算成回放步骤, 回放时重做本地步骤 |
| `replay/library.lua` | 扫描 `*.replay.json`, 解析列表字段, 判断能不能回放, 缓存与分页 |
| `replay/session.lua` | 等存档线程写完, 装上写入拦截, 结束后读回进度与设置 |
| `replay/player.lua` | 两种入口共用的回放驱动, 游戏内以回调结束而不是退出进程 |
| `replay/input_lock.lua` | 输入锁, 中止的按住时长与进度 |
| `ui/replay_menu.lua` | 选项菜单里的回放入口, 列表页与确认页 |
| `ui/settings_tab.lua` | 本 mod 的设置页: 录像开关, 保留方式, 状态 |

- 列表用 `SMODS.NFS` 按目录取一次信息 (`getDirectoryItemsInfo`), 只解析文件名, 大小与修改时间有变化的
  文件; 解析出的 `snapshot` 与 `actions` 不留着, 真正开始时由 player 重新读一遍文件.
- 写入拦截换的是 `G.SAVE_MANAGER.channel` 与全局的 `compress_and_save`, 不碰录像输出 (录像不走存档写入).
  读档开局的临时存档文件在这里放行并登记, 结束时删掉.
- 恢复分两步: 先 `load_profile` 从磁盘读回当前档位 (磁盘没被改动, 读到的就是回放前的状态), 再按开始前
  取的内存快照把解锁, 发现, 累计数据与设置放回去. 这两步都在拦截还装着的时候做, 期间游戏标脏的保存请求
  会被丢掉, 之后才按恢复后的状态落盘.
- 互斥: 回放期间 `BB_CONTROL.owner()` 为 "回放", balatrobot 的 mode `apply()` 因此停掉外部监听并锁定切换;
  内置 loop 的 `can_start` 也据此拒绝启动. 开始前若内置 loop 在运行, 确认页的开始按钮不可点.
- 录制器的开关与文件名前缀运行时可设 (`record/recorder.lua` 的 `set_enabled` / `set_prefix`):
  游戏内回放选了录像时按 `replay-` 前缀录, 结束或开始失败时回滚. 录像本来关着时, 这一步才装载编码相关的
  模块并挂上钩子; 回放文件由 `log.lua` 补写, 因为录制器的开局钩子在这种情况下装得比它晚, 开局那一刻录像段
  还没建立.
- 回放文件不走 `love.filesystem` 的写包装, 写完后单独通知 Android 修正权限 (见 [android.md](<android.md>)).
