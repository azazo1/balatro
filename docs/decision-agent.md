# Decision 模型接入

内置 agent 提供 LLM, Decision, 混合三种方式, 共用暂停, 手动接管和录像入口.

## 选择方式

| 内置方式 | 所需连接 | 操作来源 |
|---|---|---|
| LLM | LLM | 模型通过动作工具控制游戏, 可返回解说与思考摘要 |
| Decision | Decision | 程序提供封闭候选, 模型选择动作, 再逐步选择参数 |
| 混合 | LLM 和 Decision | LLM 提出 1 至 4 个单步候选, Decision 选择或批准, 程序执行 |

Decision 使用 System One 接口, 请求包含 `model`, `state`, `questions`, 返回类型化 `answers` 与 `usage`.
它不生成自由文本或工具参数, 也不返回思考流. 游戏里显示的 "Decision 选择中" 与动作描述由程序生成.
需要详细对局解说时使用混合方式, 解说沿用被选中候选的 LLM `reason`.

## 配置和操作

1. 打开 模组 -> balatrobot -> 配置, 将 agent 切到内置. 从外部切换时先切关闭.
2. 在顶部选择 LLM, Decision 或混合. 页面会说明当前方式缺少哪些连接.
3. LLM 连接在 LLM 子页填写. Decision 子页先选择 TypeSafe 或 AIHubMix, 再点 "应用预设".
4. endpoint, 模型与 key 从剪贴板粘贴. 预设会替换 endpoint / 模型 / 鉴权, 保留已有 key. 切平台后核对 key 所属平台.
5. 在 Decision 子页点 "测试连接". 测试会产生少量用量, 不执行游戏动作; 可取消, 退出设置页也会取消.
6. 对局子页设置策略, 固定种子, 赢后处理, 局后处理与单局 token 上限.
7. 从选项菜单打开 Agent 面板并点开始. 主菜单开始会选择牌组与赌注, 局内开始从当前状态继续.

| Decision 预设 | endpoint | 模型 | 鉴权 |
|---|---|---|---|
| TypeSafe 官方 | `https://api.typesafe.ai/v1/systemone` | `jev-latest` | Bearer |
| AIHubMix | `https://aihubmix.com/v1/systemone` | `jev-1.13` | Bearer |

主要兼容目标是 [TypeSafe 官方 API](https://docs.typesafe.ai/api) 和 [AIHubMix Jev 文档](https://aihubmix.com/model/jev-1.13/llms.txt).
模型版本与账户可用性以各平台为准. 单元测试验证请求格式和客户端行为, 不代表已用真实 key 验证服务.

其他提供 System One 的平台可选自定义. 支持完整 `/systemone` 地址与 OpenRouter `/alpha/decisions` 地址,
或在 API 根地址后自动补 `/systemone`; 保留查询串. 鉴权可选 Bearer, 原始 Authorization, `x-api-key`.
不根据域名自动猜测鉴权或转换协议. 普通 OpenAI Chat / Responses 地址不能作为 Decision 接口使用.

LLM 与 Decision 连接分开保存, key 不互相复制. 配置版本 v4 将旧版顶层连接迁移到 `llm`, 默认仍为 LLM.
连接, 内置方式和对局选项在开始时冻结, 运行或暂停期间停止后才能修改. 消息显示与节奏可以即时修改.
key 与现有配置一样以本地明文保存, 界面只显示掩码, 不写日志和转录.

## 独立 Decision

每次请求携带当前可观察局面, 卡牌效果, 牌型数值, 策略和最近最多 20 次动作结果. 不携带有序摸牌堆或隐藏牌身份.
每次都重新构造完整观察, 不沿用 LLM 的 "这张牌以前介绍过" 缓存. 输入按字节预算保守限制,
先丢较早动作记录, 当前观察仍超过预算时暂停, 不截成半个局面.

动作选择覆盖开局, 选盲注, 跳盲注, 重掷 Boss, 出牌, 弃牌, 买卖, 使用消耗牌, 刷新商店, 离开商店,
卡包选择与跳过, 手牌 / 小丑 / 消耗牌重排. 容量考虑负片, 钱考虑信用额度, 强制选中牌自动保留.
消耗牌与卡包使用共享的目标数量规则, 特殊卡如 Aura 与 Ankh 分别处理. 无法适配的目标规则会暂停.

选择带参数的动作后再问参数. 出牌与弃牌逐张选择, 达到合法最少数量后才出现完成项; 重排选择移动的牌与目标位置,
程序生成完整排列. 不枚举所有手牌组合或排列. 超过 255 个候选时分组继续选择, 单次动作最多 64 次子请求.
参数完成前不点击任何游戏牌. 执行前重新检查局面与合法性, 等解说退去期间局面变化也会作废.

这里提供的是局部合法候选, 不保证每项战略上合理. 游戏端点仍会检查实际规则.
同一个动作连续失败 3 次, 或连续 3 次只重排, 会暂停以避免失控.

## 混合 Decision

LLM 可直接使用查询与 `notify`, 动作通过仅内置可见的 `propose_actions` 提案. 外部 RPC 没有新增这个方法.
每个候选都是一个 `method + params + reason`, 不支持含前后依赖的动作序列. 本地先校验参数与阶段并去重:

- 2 项及以上合法候选用 Choice 选择.
- 仅剩 1 项用 Noul 判断是否应执行, 接受条件至少为 `0.5`, 同时满足设置阈值.
- 没有合法候选或唯一候选被拒绝时, 向 LLM 返回反馈再提案; 连续 3 次无可执行提案暂停.
- 网络失败, 无效答案或置信度不足时暂停, 不绕过 Decision 执行动作.

工具结果告诉 LLM 实际选中动作, confidence 与执行结果, 并带新状态. 同一轮完成一个提案动作后, 剩余调用补齐未执行结果,
后续动作必须基于新状态重新提案. 暂停或作废也补齐每个原始工具调用的结果,
保留 Chat, Responses 与 Anthropic 所需的调用配对. 候选选择不会修改原来的 assistant 工具调用内容.

## 置信度与运行控制

最低置信度可选不限制, `0.5`, `0.7`, `0.9`, 默认不限制. Choice / Score 保留服务端独立返回的 confidence,
不由最高候选概率重新计算, 也不能当成正确率. Noul 返回的是 yes 的概率, 唯一候选按这个值判断是否批准.

右上角显示当前 LLM 或 Decision 请求阶段. 独立 Decision 没有对话上下文条, 混合方式的上下文条仅反映 LLM.
Agent 面板同时列出合计和两个来源的请求 / token 用量, 最近一次 Decision 选择与 confidence.
单局 token 上限统计两个来源的合计, 包括分层参数请求; 平台不返回 usage 时无法准确计算实际消耗.

暂停取消尚未完成的模型请求, 恢复后重新观察. 已开始的游戏动画等结束, 等解说期间尚未执行的旧调用在停止后作废.
手动接管作废旧计划, 停手 1.5 秒后重新观察. 自动结算, 解锁弹窗, 胜利与无尽模式共用原有生命周期规则.

Decision 返回普通 JSON, 不使用 SSE. 客户端支持分片收集, 超时, 取消和有界重试; `429` / `5xx` 等暂时错误使用退避,
`401` / `403` 等鉴权错误不重试. 日志只保留脱敏连接信息. 转录记录问题, 答案, 候选, confidence, 耗时与用量,
录像模型来源记录对应的 endpoint 与 model, 不把模型编造成输出过思考文本.

## 验证

运行 `just test-agent` 验证配置迁移, 请求编码, 非流式传输, 重试取消, 目标约束, 分层选择, 隐藏信息,
独立循环与混合历史配对等行为. `just mods-check` 检查 mod 边界与装载约定.
真实 TypeSafe / AIHubMix 服务, 完整游戏实机对局和 Android 真机需通过游戏设置页验证, 不能由假网络测试替代.
