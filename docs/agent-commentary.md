# agent 解说规范

观众只看得到游戏画面和右侧的消息, 看不到 agent 读到的状态 JSON. 解说要让观众跟得上:
看到了什么, 在比较什么, 为什么这么做, 大概能拿多少分.

## 两种消息

| 方式 | 显示 | 用途 |
| --- | --- | --- |
| `notify {"message", "title"}` | 标题为 `title`, 默认等观众读完才返回 | 观察, 对比, 计划, 复盘. 一条讲一件事 |
| 操作参数里的 `reason` | 标题为操作名 (出牌, 购买等), 与操作同时出现 | 一句话点明这一步做什么 |

- 先 `notify` 讲清楚, 再带 `reason` 执行操作. 不要把整段分析塞进 `reason`.
- `notify` 默认 `wait: true`, 按字数等阅读时间后才返回, 连续调用时消息一条接一条出现, 不用自己 sleep.
  屏幕上最多同时 3 条, 上一条还没退场时下一条就会叠上来, 方便对照.
- 每条 30~60 字为宜, 最长显示 12 行. 讲不完就拆成几条.
  长消息叠在一起放不下时, 最旧的一条提前滑出.
- `title` 用 2~4 字分类, 例如 `商店`, `对比`, `计划`, `估分`, `Boss`, `复盘`.

## 名称与数值

- 小丑, 塔罗, 星球, 幻灵, 优惠券, 标签, Boss 一律用中文名. 状态里给的是英文名和 key,
  按 key 在 [卡牌目录](game/cards/) 查中文名, 例如 `j_blue_joker` 是 蓝色小丑.
- 第一次提到某张牌时顺带一句功能, 例如 "蓝色小丑: 牌堆每剩 1 张 +2 筹码".
- 牌型用中文: 高牌, 对子, 两对, 三条, 顺子, 同花, 葫芦, 四条, 同花顺.
- 分数写成 "筹码 x 倍率 ≈ 总分" 的大致算式, 并和目标分比较, 不必精确到个位.

## 各环节讲什么

开局: 牌组, 赌注, 大致打算 (例如 "红色牌组多 1 次弃牌, 先找能加倍率的小丑").

选择盲注:
- 目标分, 当前牌力大概能打多少.
- Boss 的效果和应对.
- 跳过时说清拿到的标签值不值, 例如 "跳过小盲注拿投资标签, 打完 Boss 多 $25, 代价是少一次商店".

出牌:
- 打什么牌型, 为什么选这几张, 留下哪些牌等后面.
- 估分: "对 K: (10+10+10) x 2, 加上小丑 +4 倍率约 180, 目标 300 还差 120, 下一手接着打".

弃牌:
- 弃哪几张, 在追什么牌型, 大致概率.
- 例如 "弃掉 3 张杂牌追同花: 手里 4 张红桃, 牌堆还剩 9 张红桃, 抽 3 张至少来 1 张的机会约 6 成".

商店: 先观察, 再决定, 最后操作. 每一步都先 `notify` 再动手.
1. 看到了什么: 在卖的小丑, 消耗牌, 补充包, 优惠券和价格, 手里的钱.
2. 现有阵容缺什么: 筹码, 倍率, 乘倍, 经济还是某个牌型.
3. 逐项对比后再买或跳过. 跳过也要比较具体好坏, 不要只说 "没有更好的".
   例如 "小丑: 每手 +4 倍率, 现有的 奸诈小丑 打对子 +50 筹码, 我们主打对子, 奸诈小丑 更划算, 不换".
   买的时候讲出具体更好在哪, 例如 "蓝色小丑 此时约 +90 筹码, 比 小丑 的 +4 倍率在当前阵容下多约 40% 分数".
4. 利息: 买之前说清花完剩多少钱, 会不会跌破 $5 的利息档.

补充包: 列出开出的几张, 选哪张, 为什么, 另外几张差在哪.

使用消耗牌: 用在哪几张牌上, 效果是什么. 例如 "海王星: 同花顺升 1 级, +40 筹码 +4 倍率".

出售与调整顺序: 为什么卖, 为什么这么排. 例如 "加倍率的放左边, 乘倍率的放右边, 先加后乘".

结算: 本轮得分对比目标, 余钱和利息, 下一步打算.

关键时刻: 险胜, 翻盘, 算错, 打赢或输掉时简单复盘. 算错了直接说, 例如 "低估了 Boss 削弱, 这手少了约 200 分".

## 语气

- 像在给朋友讲自己为什么这么打. 可以有点情绪, 但不要夸张, 不堆感叹号.
- 每条都要有具体内容: 牌名, 数值或比较. 不说空话, 例如 "让我想想", "好的".
- 不提 API, JSON, 方法名, 自己是 agent 等幕后的东西.
